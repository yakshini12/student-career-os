What the app does

Student Career OS is a local career workspace for a student targeting backend internships. It keeps a profile, practice snapshot, projects, evidence, sample opportunities, and applications in one state. From an opportunity it computes a rule-based fit, ranks concrete next actions, and sends gated evidence through a verification workspace. Passing the gate creates verified evidence and recomputes fit. Nothing is stored twice: fit, coverage, and rankings are calculated on read.

Three-stop reference route

This is a reference route, not a record of a guided tour. Paths are relative to the repository root.

  1. Start at the dispatch. Open src/views/VerificationView.tsx. Find run() around line 71. It dispatches { type: "RUN_VERIFICATION", runAt } only after a valid bundle is pending. The submit path above it is submit(), which dispatches SUBMIT_ARTIFACT.
  2. Follow the transition. Open src/model/state.ts. In reduceWorkspace, find case "RUN_VERIFICATION" around line 274. The reducer calls runContainerizationChecks, returns to Unsupported on failure, or atomically writes the verified evidence item (line 301), marks the milestone done, appends history, and stores the verified evidence ID.
  3. See why the number changed. Open src/model/fit.ts. containerizationRow() around line 440 reads the verification status plus verified evidence; computeFit() around line 524 maps every requirement. src/store/selectors.ts exposes selectedCoverage and selectedActions, which Today and the opportunity detail render.
Where the visible verified card comes from

src/components/EvidenceCard.tsx checks evidence.source === "verified" and renders the Verified stamp and the “Editing and removal are locked until reset” note. src/views/ProjectsView.tsx withholds edit and remove handlers for verified evidence.

To change this, start here

Change a check rule

Edit the relevant check(...) call in src/model/verification.ts, then update src/test/verification.test.ts. The incomplete bundle must still fail only checks 6 and 8.

Change scoring or ordering

Edit the impact and effort tables in src/model/actions.ts. The ranking formula is impact × urgency ÷ effort; tie-breakers live in the same file.

Change what fit reads

Start in src/model/fit.ts. API, database, deployment, testing, documentation, collaboration, and data pipeline each have their own evaluation function. Capabilities alone never create Partial.

Change the seed or copy

Seed data is in src/data/seed.ts; shared labels and disclaimers are in src/data/copy.ts. Keep every opportunity labelled Sample — not live.

A practice to reuse

Write the observable contract before wiring the UI. This project’s verification contract is concrete: the incomplete sample must pass 6 of 8 checks and fail exactly Command and Port mapping; the complete sample must pass 8/8; a pass must create ev_campus_container_verified with matching timestamps and move coverage from 2 of 5 to 3 of 5. Those statements are encoded in src/test/verification.test.ts, src/test/state.test.ts, and src/test/journey.test.ts.

Because the expected output was written down first, a broken parser or a UI that skipped the atomic evidence write would fail a test instead of quietly producing a believable demo. On another project, turn the riskiest user-visible claim into one exact before/after assertion before building the screen around it.

The app is a local proof of concept with synthetic data. It has no backend, accounts, live opportunity feed, platform sync, LLM matching, or application submission. The verification gate inspects bundle text only; it does not build an image or run a container. Deployment evidence is self-reported and cannot become Supported.
